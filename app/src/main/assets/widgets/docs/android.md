# The phone's data

Part of the widget docs: README.md, one folder up, comes first, and paths here are from the widgets folder.

Sources that read Android, so they work without Linux. Each updates as what it reads changes, unless it says it's polled.

| source | gives |
|---|---|
| `source bat = android.battery` | `{level, charging, status, temp, voltage, health, plugged, technology, cycles}` from Android, updated as it changes (`temp` in °C, `voltage` in V; `health`, `plugged`, `technology` and `cycles` are null when the phone doesn't say). The current, the mAh left, the time to full and the charger are in `android.power` (owl 15) |
| `source dev = android.device` | the phone: `{model, maker, android, sdk, soc}` (the Linux side can't see these) |
| `source sys = android.system every 5s` | the phone's state, polled: `{kernel, uptime, memory, storage, cpu, display, build, codename, patch, locale, timezone, launcher, theme, apps}`. `uptime` is in seconds; `memory` is `{total, used, available}` and `storage` `{total, used, free}`, in bytes; `cpu` is `{soc, maker, hardware, cores, abi, maxMhz}`; `display` is `{width, height, hz, dpi}`; `patch` is the security patch date, `launcher` this launcher's version, `theme` the Omarchy theme's name and `apps` how many Android apps are installed. See `20-fetch.owl` (owl 5) |
| `source n = android.network every 2s` | the bytes the phone received and sent since it booted, polled: `{rx, tx, mobileRx, mobileTx, uptime}`. `rx` and `tx` count every network, `mobileRx` and `mobileTx` mobile data alone (so `n.rx - n.mobileRx` is mostly Wi-Fi), each null on a phone that doesn't count it; `uptime` is when they were read, in seconds since boot with milliseconds. A rate is the change in bytes over the change in `uptime`, not over `every`: polling stops while the widget is off screen, so the gap after it comes back is longer. The counters start over when the phone reboots. No permission needed (owl 13). `on n { if old != null && value.rx >= old.rx && value.uptime > old.uptime { down = (value.rx - old.rx) / (value.uptime - old.uptime) } }`, then `fmtBytes(down) + "/s"` |
| `source p = android.power every 2s` | the battery's current and charge, and the charger, polled, as Android doesn't say when the current changes: `{current, currentAvg, watts, charge, chargeTime, maxCurrent, maxVoltage}`. `current` is in mA, positive while charging and negative while draining, the same on every phone, and `currentAvg` the phone's average of it; `watts` is `current` times the battery's voltage, signed the same way; `charge` what the battery holds now, in mAh; `chargeTime` Android's estimate of the seconds until full, while charging; `maxCurrent` (mA) and `maxVoltage` (V) what the charger offers, while plugged in, so `p.maxCurrent * p.maxVoltage / 1000` is its watts and tells fast charging from slow. Each is null where the phone doesn't say. Level, temperature and voltage are in `android.battery`. No permission needed (owl 15) |
| `source m = android.media` | what's playing in any app on the phone: `{available, playing, title, artist, album, app, package, position, duration, art}`, updated as it changes (`position` and `duration` in seconds; `art` goes in `Image { src: m.art }`). `available` is false until the user grants notification access; `media(...)` opens that setting then. See `examples/97-now-playing.owl` |
| `source n = android.notifications` | the phone's notifications, newest first, updated as they come and go: `{available, count, items}`, each item `{key, app, package, profile, icon, title, text, time, clearable, actions}` (`time` in Unix seconds; `profile` is `work` or `clone` for a notification from a work profile or a cloned app, else null; `icon` is the app's icon for `Image { src: i.icon }`, from that profile, owl 7; `actions` is its buttons as the shade shows them, each `{title, reply}`, where `reply` is true for one that takes typed text, owl 13). Ongoing ones (music, downloads) are left out. Needs the same notification access as media. See `examples/98-notifications.owl` (owl 4) |
| `source v = android.volume` | the media volume: `{level, muted, steps}` (`level` in percent, `steps` how many the phone has), updated as it changes. Set it with `volume(...)` (owl 4). The other streams have the same fields under `v.ring`, `v.notification` and `v.alarm`, set with `volume(level, "ring")` (owl 13). `v.output` is where media plays, `{type, name}`: `type` is `speaker`, `bluetooth`, `wired`, `usb`, `hdmi` or `dock` (more may come: show the word for one you don't know), and `name` the device's name (`Pixel Buds`), null where it has none, like the speaker and most wired headphones. Android doesn't say which output a stream uses, so with several it's the one Android picks first: Bluetooth, wired, USB. `settings("output")` lets the user pick another (owl 13) |
| `source a = android.alarm` | the next alarm set in any clock app: `{set, time, app}`, updated as it changes. `time` is in Unix seconds (`fmtTime(a.time, "EEE HH:mm")`, or `at a.time`), `app` the clock app's package (`androidApp(a.app)`); both null when no alarm is set (owl 7) |
| `source a = android.apps` | the phone's launchable apps, updated as they're installed, removed and opened: a list of `{key, name, package, component, profile, system, icon, score, last}`. `key` is unique even with the same app in a work profile or a clone, and `androidApp(a.key)` opens that copy; `profile` is `work` or `clone` for those, else null; `icon` goes in `Image { src: a.icon }`. `score` and `last` (Unix seconds, null if never opened) are what the search ranks by: opens fade by half every two weeks, and `androidApp(...)` counts like opening from the drawer (owl 8) |
| `source ag = android.agents` | the coding agents installed in Linux: `{default, installed}`, each agent `{bin, name, description, command, key, icon}`, updated as they change. `default` is the one the prompt bar asks and `ask(text)` sends to, null with none installed; `open(a.key)` starts one without a prompt, and `icon` is its logo (owl 10) |
| `source r = android.recent` | the apps in the recent strip above the prompt bar, last opened first: a list of `{key, kind, name, icon, score, last}`, Android and Linux apps, owl apps and shortcuts alike (`kind` is `android`, `linux`, `owl` or `shortcut`). `open(r.key)` opens one, `icon` goes in `Image { src: r.icon }`, and `score` and `last` are as in `android.apps`. Like the strip, it reorders once home is out of sight, not under the finger that tapped (owl 10) |
| `source d = android.drawer` | the app drawer: `{apps, linux, monochrome, work, updates}`, updated as it changes. `apps` lists every app in the drawer's order, owl apps, Linux apps, shortcuts and Android apps, then the work profile's shortcuts and apps, each `{key, kind, name, label, icon, hasIcon, initials, profile, alias, paused, actions, score, last}`: `kind`, `icon`, `score` and `last` as in `android.recent`, `label` what screen readers should say for it, for an Image's `label` ("WhatsApp work"), `profile` as in `android.apps`, `alias` what search matches besides the name (`WhatsApp work`), `paused` for an app in a paused work profile (the drawer dims those), and `actions` the words of its long-press menu for `appAction(word, a.key)`. `hasIcon` is false while `icon` would draw nothing (no icon, or not loaded yet), when the drawer shows `initials` on a badge instead; `monochrome` on `d` says icons are silhouettes, which the drawer puts on a badge too. `d.linux` is `installed`, `installing` or `missing`; `d.work` is `{paused}` while there's a work profile, else null; `d.updates` is how many system updates wait, the dot on the drawer's settings button. `open(a.key)` opens one (owl 11) |
| `source kb = android.modifiers` | how the key bar holds each modifier: `{ctrl, alt, shift}`, each `off`, `once` (for the next key, tapped or typed) or `locked` (until it's set off). `latch(...)` sets them; see docs/keybar.md (owl 12) |
| `source m = android.modes` | the phone's modes: `{dnd, saver, ringer, torch}`, updated as they change. `dnd` is Do Not Disturb in any form, `saver` battery saver, `ringer` is `normal`, `vibrate` or `silent`, and `torch` is null on a phone without a flash. Switch the torch with `torch(...)` (owl 7). Since owl 13 `torchLevel` is its brightness in percent, what it shines at or turns on at, and null where it can't be dimmed. A torch has a few steps, not a hundred, so it reads back the nearest step: `torch(40)` on a torch with three is 67. Since owl 13 also `airplane`, `wifi`, `bluetooth`, `location`, `rotate` (auto-rotate), `dark` (the system's dark theme), `brightness` (in percent, as Android stores it, which the curved settings slider may show differently) and `autoBrightness`. Android lets a launcher read these but not switch them: `settings("wifi")` opens its own panel for that. `dnd` it can switch, with `dnd(...)`, and `dndAllows` says what gets through: `all` (Do Not Disturb is off), `priority` (the user's exceptions), `alarms` or `none` (total silence, alarms too). `dnd(m.dndAllows)` sets back what it read (owl 13) |
| `source s = android.sim` | the SIM and the mobile network: `{available, present, carrier, signal, data, roaming}`, updated as they change. `available` is false on a phone without mobile service, like a Wi-Fi tablet; `present` whether a SIM is in and unlocked; `carrier` the network's name (another's while roaming), else the SIM's; `signal` 0 to 4 bars; `data` whether mobile data is on. `carrier`, `signal` and `data` are null without a SIM, and `data` too on a phone that hides it. Every phone gives every field, so a tablet's is `{available: false, present: false, carrier: null, signal: null, data: null, roaming: false}`. The network type (LTE, 5G) and which SIM takes calls need the phone permission, which this launcher doesn't ask for. No permission needed (owl 13) |
| `source said = android.speech` | dictation: what you say after tapping a node with `speech("start")` or `speech("toggle")`, as text. `{available, listening, text, final, error}`: `available` whether the phone has a speech recognizer; `listening` whether the microphone is on for this widget; `text` what has been heard so far, updated as you speak, for showing; `final` all of it once the dictation ends, and `""` from its start, so `on said.final { if value { ... } }` runs once for each dictation, also when the same words come twice: what to send on, as `text` changes many times while you speak: `on said` or `on said.text` would run for every word, and a command in it would run with half-heard sentences. `error` says why it couldn't listen, like `microphone permission needed`, else null. It listens across pauses until `speech("stop")`, and stops as the widget stops showing: its screen closed, home or the app gone to the background. One widget listens at a time, and each reads only its own: the others see `listening` false and nothing heard. The phone recognizes the speech, on the phone where it can; only the text reaches the widget. The first start asks for the microphone. The phone may play a short sound as dictation stops. There's no language to pick: it's the phone's. In `on said.final`, unlike other triggers, `typeText` and `pressKey` work, for the words just heard: `on said.final { if value { typeText(value + " ") } }` dictates into the Linux window you're typing in (owl 15) |
